> 技术选型与实施路线 · 2026-10-19 留档 · 配套文档：[产品分析](产品分析.md)
>
> 状态：M0（工程骨架）已落地。**v2 修订（同日）：按「自由度对标 Premiere」原则重构**，修订记录见第 8 节。

## 1. 结论先行

- 技术栈跟随集群既定套路：**Tauri 2 + React 19 + Vite 8 + TypeScript 6 + zustand**，UI 基础设施来自 **@baigong/fang**（剪是 fang 的第一个真实消费方）。
- 媒体引擎用 **ffmpeg/ffprobe**：Rust 侧封装命令执行，前端不碰进程。
- **第一设计原则：编辑自由度对标 Premiere，不被里程碑封顶。** 手段是「模型一次立全、UI 渐进解锁」：数据模型（序列/轨道/属性/效果/关键帧）从第一天起就是自由度完备的形状，里程碑只决定哪些交互能力开放给用户，模型层永不返工。
- 里程碑：M1 通用闭环（多轨时间线）→ M2 空间与编辑自由 → M3 时间自由与工程化 → M4 效果自由 → M5 PR 级进阶。

## 2. 自由度对标 Premiere（本方案的纲领）

PR 的「自由」拆成六个维度。每个维度先定**架构承诺**（保证上限不低于 PR），再定 UI 解锁的里程碑——承诺在模型层立即兑现，UI 可以晚到。

| 维度 | Premiere 的自由度 | 剪的架构承诺（模型层，立即生效） | UI 解锁 |
| --- | --- | --- | --- |
| 时间线 | 任意数量 V/A 轨、任意排序；插入/覆盖、波纹删除、滑移/滑动、轨道锁定 | 轨道＝无限数组，V/A 分离无固定槽位；剪辑块只有位置约束没有「特殊轨」 | M1 增删轨/排列/分割；M2 修剪三式/波纹/吸附 |
| 空间（画布） | 每块素材独立位置/缩放/旋转/锚点/不透明度；任意画布分辨率 | 每个剪辑块携带完整变换属性（transform），合成按层叠加而非铺满画布 | M2 画布拖动/缩放手柄 |
| 属性（关键帧） | 位置/缩放/旋转/不透明度/音量/任意效果参数均可打关键帧＋缓动曲线 | 所有可动画属性统一为 `Animatable<T>`（静态值或关键帧轨），属性求值统一走插值器 | M3 关键帧 UI＋曲线编辑器 |
| 效果 | 效果任意堆叠/排序/开关/预设；转场任意时长任意剪辑点；调整图层、嵌套序列 | 效果＝纯数据描述（id+参数+关键帧）的可堆叠链，预览与导出双端注册实现 | M4 效果库/参数/转场/嵌套 |
| 时间（变速） | 任意速率、时间重映射（速度曲线）、倒放、定格 | 剪辑块带 `speed`，时长＝(源出点−源入点)/速率 的推导式，模型不假设 1x | M3 变速 UI；速度曲线 M3 末 |
| 音频 | 轨道独奏/静音、块级增益/声像、效果、混音台 | 块级与轨级音频属性齐备（Animatable），轨道带 solo/mute/lock | M2 静音/增益；M5 混音台 |

**工作区自由**（面板停靠/浮动/自定义工作区）也属 PR 体验，但依赖 fang Dock 演进（首版无拖拽），列入 fang 需求反哺池（第 6.4 节），M5 处理。

兑现承诺的关键机制是第 3.3 节的「合成求值层」：预览与导出消费同一份对时间轴的求值结果，任何属性组合都不会出现「预览得到、导不出」。

## 3. 架构

### 3.1 目录与分层

```
src/                          # 前端（UI 与编排层）
├─ shell/                     # 应用外壳：TopBar + DockHost 布局（fang）
├─ core/                      # 核心逻辑（不含 UI，可单测）
│  ├─ project/                # 工程数据模型（types.ts）+ store + 序列化
│  ├─ composite/              # 合成求值：任意时刻 t 的帧描述（预览/导出共用的真相层）
│  ├─ media/                  # 素材：导入、probe 缓存、缩略图、波形
│  ├─ playback/               # 播放引擎：时钟、帧调度、video 池 / canvas 合成渲染
│  └─ export/                 # 导出：帧描述序列 → ffmpeg filter_complex、进度
├─ features/                  # UI 功能模块（一一对应界面区域）
│  ├─ media-bin/  preview/  timeline/  inspector/
└─ styles/

src-tauri/src/                # Rust 侧（M0 仅插件注册，M1 起增）
├─ lib.rs  ffmpeg.rs  probe.rs
```

分层规则：`core/` 不 import `features/`；`features/` 经 zustand store 读写 `core/`；Rust 命令只被 `core/` 调用。

### 3.2 数据流

```
用户操作 → features(UI) → store 修改工程文档（纯数据）
                        ↘ composite：求值任意时刻的帧描述（RenderTree）
                            ↘ playback 渲染 RenderTree（canvas）
                            ↘ export 把 RenderTree 全程翻译成 ffmpeg 命令
```

工程文档是唯一事实源。撤销/重做（M2）在 store 写入层做快照栈，文档纯数据保证快照廉价。

### 3.3 合成求值层（自由度的技术保障，M1 立骨架）

`composite/evaluate(doc, timeUs) → FrameDescription`：给定时刻，输出该帧的全部可见层——每层的源片段、已解算的变换/不透明度（关键帧已插值）、效果链参数、音频增益/声像。

- **canvas 预览器**（M2 起）逐帧渲染 FrameDescription；
- **ffmpeg 导出器**（M1 起）按同一求值逻辑生成 filter_complex（overlay 链：每层 setpts/trim/缩放/旋转/透明度/位置/效果 → 按轨道序叠加）。

两端共享求值，保证「所见即所得」在任意属性组合下成立；效果新增＝在双端注册表各注册一个实现。

### 3.4 数据模型（v2，已落于 `src/core/project/types.ts`）

- `ProjectDocument { version: 2, name, assets[], sequences[], activeSequenceId }`——**序列是一等公民**，多序列工程，序列可作素材嵌套（M4 UI）。
- `Sequence { fps, width, height, tracks[] }`——轨道无限数组，V/A 分离；`Track` 带 locked/muted/solo/height。
- `Clip`：`sourceInUs / sourceOutUs / speed` 推导时间线时长（变速是模型一等能力）；携带 `transform`（x/y/scale/rotation/opacity，全部 Animatable）、`audio`（gain/pan，Animatable）、`effects[]`（可堆叠效果链）、`transitions`（出入转场）。
- `Animatable<T>`：`{ value }` 或 `{ keyframes: Keyframe[] }`——静态值是关键帧轨的退化情形，属性从静态升关键帧**不改结构**，这是属性自由度不打折的机制。
- 时间单位一律微秒（integer 语义 number），帧率只参与取整换算。

### 3.5 预览渲染分阶段

| 阶段 | 方案 | 能力边界 |
| --- | --- | --- |
| M1 | HTML5 `<video>` 元素池：播放头落在哪个块就显示/播放哪个 | 单层取景（transform 有值但只显示主层），够 M1 交互 |
| M2 | Canvas 层合成：rAF 时钟驱动，按 FrameDescription 逐层绘制（含 transform/不透明度） | 多轨叠加、画布操纵、转场预览 |
| 后置 | WebCodecs 帧级解码 | 精确逐帧/倒放，推迟池 |

音频：M1/M2 用 video 元素自带音频；独立音频轨混音走 WebAudio（M2 设计，M5 混音台）。

### 3.6 技术选型明细

| 项 | 选择 | 出处 |

## 6. 风险与依赖

### 6.1 已知风险

- 导出一致性：预览（浏览器解码）与导出（ffmpeg）是两套解码器。对策：双端共享 FrameDescription 求值（3.3）压缩分歧面到「解码器本身」；导出后校验时长差 < 一帧。
- 求值性能：每帧对全属性插值＋全层求值。对策：composite 层做增量缓存（脏标记按 clip 粒度），M2 压测。
- video seek 精度：关键帧间 seek 有误差。M1 容忍 ±1 帧；不满足则 WebCodecs 提前。
- 时间线渲染规模：长工程剪辑块多。M2 视口虚拟化。
- 关键帧插值语义（贝塞尔缓动的时域/值域映射）是易错点，M3 用黄金用例集测试。

### 6.2 对 fang 的反哺需求（按里程碑提交）

- M2：Timeline 场景大量用滑杆/数值输入 → fang `ui/` 通用控件需求从这里沉淀。
- M3：快捷键体系（JKL/S/Ctrl+S 等）直接用 fang `useHotkeys`，缺什么补什么。
- M5：面板停靠拖拽/浮动/工作区预设 → fang Dock 演进的最大需求来源。

### 6.3 外部依赖

- ffmpeg sidecar 下载源（GitHub Releases）；CI 与本地首次需联网下载。

### 6.4 推迟池

专业调色（示波器）、动效模板、协同、AI 辅助、WebCodecs 帧级预览、大素材流式读取、混合模式/遮罩（M4 视效果框架成熟度可提前）、亮色主题、图标定制。
