# 百工·剪（Jian）开发方案

> 技术选型与实施路线 · 2026-10-19 留档 · 配套文档：[产品分析](产品分析.md)
>
> 状态：M0（工程骨架）已落地，方案随里程碑推进滚动修订。

## 1. 结论先行

- 技术栈跟随集群既定套路：**Tauri 2 + React 19 + Vite 8 + TypeScript 6 + zustand**，UI 基础设施来自 **@baigong/fang**（剪是 fang 的第一个真实消费方）。
- 媒体引擎用 **ffmpeg/ffprobe**：Rust 侧封装命令执行，前端不碰进程。
- 交付节奏分五个里程碑，**M1 交付最小可用闭环**（导入→剪→预览→导出），高级能力按产品分析的「可后置」清单排队。

## 2. 目标与范围

产品分析定义的核心职能是以时间线为中心的多轨非线性剪辑（NLE）。本方案把「必备核心能力」拆进 M1–M4，「可后置高级能力」全部进推迟池（第 7 节），不在本方案展开设计。

## 3. 技术选型

### 3.1 沿用集群既定（不做二次论证）

| 项 | 选择 | 出处 |
| --- | --- | --- |
| 桌面外壳 | Tauri 2（Rust 侧轻量起步，仅官方插件） | zhi 先例 |

### 3.2 视频特有决策

**媒体引擎：ffmpeg/ffprobe（外部进程）**，不引入 libmpv / WebCodecs 做编解码主力：

- probe（时长/分辨率/帧率/音轨）→ 导入元数据；
- 抽帧缩略图（时间线剪辑块的胶片条）；
- 波形（ffmpeg 解 PCM，前端采样绘制，M2）；
- 导出合成（时间线 → filter_complex 命令）。

理由：生态最全、格式覆盖最广、导出正确性有保障；进程隔离崩溃不伤主程序。代价：命令行拼接复杂（收敛在 Rust 侧单模块）。

**ffmpeg 分发：Tauri sidecar 打包进安装包**（`src-tauri/binaries/`，不入库，`scripts/fetch-ffmpeg.mjs` 下载）。理由：用户零依赖、版本行为可预期；代价：安装包体积 +80MB 左右。**M0 骨架不引入，M1 落地**（骨架阶段无媒体功能，先用不上）。

**预览渲染分阶段**：

| 阶段 | 方案 | 能力边界 |
| --- | --- | --- |
| M1 | HTML5 `<video>` 元素池：每素材一个隐藏元素，播放头落在哪个剪辑块就显示/播放哪个 | 单轨单层预览，够用 |
| M2 | Canvas 合成：rAF 时钟驱动，video 元素降级为解码器，逐帧把各轨画面画上画布 | 多轨叠加、字幕、转场预览 |
| 后置 | WebCodecs 帧级解码 | 精确逐帧、倒放等，真实需求出现再上（推迟池） |

音频：M1/M2 直接用 video 元素自带音频输出，独立音频轨的混音走 WebAudio（M2 设计）。

### 3.3 fang 消费方式（现阶段）

registry 未搭建（fang 侧推迟项），走 **alias 本地联调轨**：

- vite：`resolve.alias` 两条规则（先长后短）＋ `dedupe: ["react"]`（fang src 内部 import react 会解析到 fang 自己的 node_modules，双 react 实例会让 hooks 崩溃，dedupe 强制归一到 jian 根）；
- tsc：`tsconfig.json` 的 `paths` 双轨同源；
- 前置：**fang 仓库需先 `npm install`**（tsc 从 fang 源文件位置向上解析 react，fang 没装依赖会报 TS2307）；
- registry 就绪后切正式 `npm install @baigong/fang`，删 alias/paths。

fang 的 API 由剪的真实需求反推沉淀（fang 定位「API 需求驱动」），不预先设计。

## 4. 架构

### 4.1 目录与分层

```
src/                          # 前端（UI 与编排层）
├─ shell/                     # 应用外壳：TopBar + DockHost 布局（fang）
├─ core/                      # 核心逻辑（不含 UI，可单测）
│  ├─ project/                # 工程数据模型（types.ts 已立）+ store + 序列化（M1）
│  ├─ media/                  # 素材：导入、probe 缓存、缩略图（M1）、波形（M2）
│  ├─ playback/               # 播放引擎：时钟、帧调度、预览渲染（M1 video 池 → M2 canvas）
│  └─ export/                 # 导出：时间线→ffmpeg 命令生成、进度（M1）
├─ features/                  # UI 功能模块（一一对应界面区域）
│  ├─ media-bin/              # 素材池
│  ├─ preview/                # 节目预览器（M1 并入源监视器打点）
│  ├─ timeline/               # 时间线：轨道、剪辑块、工具条
│  └─ inspector/              # 效果控件（M2）
└─ styles/

src-tauri/src/                # Rust 侧（M0 仅插件注册，M1 起增）
├─ lib.rs                     # 插件 + 命令注册表
├─ ffmpeg.rs                  # sidecar 路径解析、执行、进度解析（M1）
└─ probe.rs                   # ffprobe JSON → 前端模型（M1）
```

分层规则：`core/` 不 import `features/`、不 import React 组件；`features/` 经 zustand store 读写 `core/`；Rust 命令只被 `core/` 调用。

### 4.2 数据流

```
用户操作 → features(UI) → core store(zustand) 修改工程文档（纯数据）
                       ↘ playback 读文档驱动预览
                       ↘ export 读文档生成 ffmpeg 命令 → Rust 执行 → 进度事件回传
```

工程文档是唯一事实源；预览与导出都是它的只读消费者。撤销/重做（M3）在 store 写入层做快照栈，文档纯数据保证了快照廉价。

### 4.3 数据模型（已落于 `src/core/project/types.ts`）

- `ProjectDocument { version, name, fps, width, height, assets[], tracks[] }`
- `MediaAsset`：一次导入一条（ffprobe 元数据），剪辑块按 `assetId` 引用；
- `Track { kind: video|audio, clips[] }`：视频轨数组靠后者渲染在上层（NLE 惯例）；
- `Clip { assetId, timelineStartUs, durationUs, sourceInUs, gain }`：三段式入账（时间线位置 × 源入点 × 时长）。

**时间单位一律微秒**（integer 语义 number）：浮点秒在长工程反复换算会累积误差，微秒在 JS number 安全整数域内绰绰有余；帧率只作为工程属性参与取整换算（一帧 = 1e6/fps µs）。

### 4.4 CI（三分支，zhi 同款）

- develop：前端门禁（tsc + vite build）＋ Rust 门禁（cargo check --locked）；
- qa：门禁复跑 + Windows NSIS 试用安装包（artifact）；
- main：门禁复跑 + 正式安装包 + GitHub Release（版本号随 `tauri.conf.json`，tag `v{version}`）。

只产 NSIS：WiX(MSI) 的 codepage 1252 编不了中文产品名（zhi 实测 LGHT0311）。M1 起 qa/main 打包前需先跑 ffmpeg 下载脚本（sidecar 就位）。

## 7. 风险与推迟池

**已知风险**：

- 导出一致性：预览（浏览器解码）与导出（ffmpeg）是两套解码器，色彩/时长可能有细微差异。对策：导出后校验时长差 < 一帧；色彩差异 M2 后专项处理。
- video 元素 seek 精度：关键帧间 seek 有误差，逐帧步进可能不精确。M1 验收容忍 ±1 帧；不满足则该路径提前切 WebCodecs（推迟池第 1 项提前）。
- 长工程性能：时间线全部剪辑块直接渲染会卡。M2 做视口虚拟化。

**推迟池**（按产品分析「可后置」+ 实施新增）：

专业调色（LUT/示波器）、音频混音台、多机位、绿幕抠像、动效模板、代理剪辑、协同、AI 辅助、WebCodecs 帧级预览、自定义协议流式读取（大素材不落盘预览）、面板拖拽重组（fang Dock 首版无拖拽）、亮色主题、图标定制。
