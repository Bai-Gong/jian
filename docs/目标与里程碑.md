## 开发目标

以时间线为中心的多轨非线性剪辑工具（对标 Premiere 核心工作流），
覆盖导入素材 → 粗剪精修 → 调色配乐 → 导出成片。纲领沿用开发方案：
「模型一次立全、UI 渐进解锁」。剪同时承担两个集群角色：**坊的第一
消费方**（外壳能力从这里反哺）、**冶的第一验收场**（冶的里程碑准入
以剪的真实使用为准）。

## 引擎线：ffmpeg → 冶（新增，对齐 ye/docs/integration.md）

当前媒体引擎是 ffmpeg/ffprobe 外部进程（sidecar 三档定位）。集群
既定方向是冶（ye，FFmpeg 替代基础库）以 Cargo 依赖进程内服务剪。
迁移按能力分步，**不阻塞功能线，两线并行**：

- **E0（现状）**：ffmpeg sidecar 承担 probe、解码、导出全部职责。
- **E1 probe 换冶**（冶 M1 的 mp4 落地后）：素材信息列出改走冶的
  进程内 probe，ffprobe 保留兜底（非 mp4 容器）。准入：剪 M1 已
  定稿 + mp4 素材信息两轨一致。**2026-10-27 代码面达成**：双引擎
  开关（engine 参数，auto=ye 优先回退 ffprobe）落地，mp4 双轨对拍
  判等全绿（含封面回退；见 m2-jian-plan 收尾实录）；准入中的
  「剪 M1 已定稿」仍欠 GUI 人工回归。
- **E2 解码换冶**（冶 M2 的 H.264 解码后）：时间线回放解码走冶，
  ffmpeg 保留导出。准入：冶一致性测试通过 + 回放流畅度不劣于
  ffmpeg 轨。
- **E3 导出换冶**（冶 M4 的 H.264 编码 + AAC 后）：导出管线走冶；
  ffmpeg sidecar 降为可选兼容包，一个里程碑周期后移除。
  准入：导出成片质量与速度对齐既有基线。
- 每步迁移保留 ffmpeg 回退开关至少一个里程碑周期；E1 落地后启用
  剪锻共享的 probe 缓存（integration.md 运行期联通点）。

## 集群对齐

- 剪 M1 定稿 = 冶 M1 准入验收；剪时间线回放 = 冶 M2 准入验收

- 剪每完成一个功能里程碑，向坊提一次反哺清单（开发方案 6.2 已列
  M2/M3/M5 三批）。
